# Canuto Framework Context

## Snapshot
- repo: canuto-framework-v1
- purpose: installer, runtime hooks, personas, skills, and vault conventions for Canuto v1.x
- primary entrypoints: `install.sh`, `.agents/`, `docs/`, `test-framework.sh`, `.agents/tools/framework-session-audit.js`

## Working Rules
- Keep installer flows idempotent for both fresh install and update.
- Prefer additive migrations over destructive rewrites of user config.
- Treat `~/.claude/settings.json`, `~/.codex/config.toml`, and `~/.canuto/vault/` as user state that must be preserved.

## Runtime Areas
- `install.sh`: project bootstrap, update, migrate, repair, doctor, and dependency setup
- `.agents/hooks/`: passive runtime integration into Claude tool lifecycle
- `.agents/tools/`: Codex review/runtime helpers, health checks, and the cross-project session audit pipeline
- `docs/`: user-facing operational guidance

## Validation
- Framework maintenance: `bash test-framework.sh`
- Cross-project audit: `node .agents/tools/framework-session-audit.js --help`
- Consumer install validation: `bash install.sh --test`
- Runtime repair + validation: `bash install.sh --doctor`
